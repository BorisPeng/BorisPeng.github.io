项目2026年3月22日

墨问 · 可对话的个人笔记库

给个人笔记加一层检索增强：提问时先找相关笔记，再让大模型基于这些内容回答。

#Flask#RAG#LLM#知识管理

想解决的问题

笔记越写越多，真正要用的时候还是靠关键词翻找。如果能让模型先读我的笔记再回答，笔记就从“存档”变成了可以追问的资料。

实现

后端用 Flask，笔记的增删改查拆成独立蓝图，数据以 JSON 文件持久化，迁移和查看都方便。问答走 RAG：提问时先在标题、正文和标签里做匹配，取相似度最高的若干条笔记，作为 system prompt 注入上下文，再调用模型生成回答，回答里带上引用来源。

模型层做成插件：DeepSeek、智谱 BigModel 共用一个基类，兼容不同版本的接口路径，换 provider 基本只改配置。回复用 SSE 流式输出，一段满意的对话可以过滤后一键存成新笔记，形成检索、提问、归档的闭环。

复盘

这是第一次把“检索 + 生成”完整串起来。关键词匹配是这一版的折中：实现简单、可解释，但召回率和语义无关，换个说法就可能找不到——下一步应该换成向量嵌入。多模型抽象倒是验证了一个判断：把厂商差异收在一个基类里，上层功能就不用为每次换模型重写。
